トレンド・ラダー戦略 v2

複数の暗号資産に等リスクで配分する、両建てのトレンドフォロー。5・14・30・60 日の 4 本のモメンタムを平均し、銘柄ごとのボラでサイズを決め、ポートフォリオ全体のボラを 15% に合わせる。1 時間ごとに判断し、目標が 0.10 以上動いたときだけ建て直す。

01ロジック

4 つの段を順に通す。前段の出力が次段の入力になるので、番号は処理の順序そのものを表す。すべて時刻 t のクローズまでに確定した情報だけで計算し、発注は t+1 のオープンで約定させる。

01

シグナル — トレンド・ラダー

銘柄ごとに、4 つのルックバック（5 / 14 / 30 / 60 日）のモメンタムをボラで正規化し、平均する。単一のルックバックを選ぶとその値への当てはめが残るため、4 本の平均でパラメータ選択のリスクを消す。

σ_t = std(Δlog P, 直近 30 本) ← 1時間足 30 本 s_L,t = clip( (log P_t − log P_{t−L}) / (σ_t·√L) / 1.5 , −1, +1 ) s_t = mean( s_120, s_336, s_720, s_1440 ) ← 5/14/30/60 日（時間）
02

更新バンド — 建て直しの間引き

毎時間きっちり建て直すとシグナルの微小な揺れにスプレッドを払い続ける。目標が 0.10 以上動いたときだけ更新し、それ以外は前回の建玉を維持する。回転率が 0.27 → 0.18 回/日 に下がり、成績はむしろ僅かに改善した。

h_t = s_t if |s_t − h_{t−1}| > 0.10 = h_{t−1} otherwise
03

サイジング — 等リスク配分と 2 段のボラターゲット

1 段目は銘柄ごと。ボラの高い銘柄ほど小さく建てるので、各銘柄のリスク寄与が揃う。2 段目はポートフォリオ全体。分散が効くと合計ボラは目標を大きく下回るため、ここで取り戻す。最後に総建玉をレバレッジ上限で頭打ちにする。

e_i,t = clip( h_i,t · (15% / σ_i,20日) , ±0.5 ) ← 銘柄ごと k_t = clip( 15% / σ_portfolio,60日 , 0.2, 5.0 ) ← 1 バー遅延で適用 E_i,t = e_i,t · k_t / max(1, Σ|e_i,t·k_t| / 2.0) ← 総建玉 ≤ 2.0倍
04

執行とコスト

t+1 のオープンで約定。片道 1.5bp（指値優先）を想定し、GMO の建玉管理料 0.04%/日は JST 06:00 をまたぐバーで課金する。コストの支配項はスプレッドではなく建玉管理料（年 4.6% のうち約 3 分の 2）。

損益_t = Σ E_i,t−1 · (Open_{t+1}/Close_t − 1) + Σ E_i,t · (Close_{t+1}/Open_{t+1} − 1) コスト_t = Σ|ΔE_i,t| · 1.5bp + 1[06:00 JST をまたぐ] · Σ|E_i,t| · 4bp

06懸念の検証

前提が崩れたらどうなるかを、限界まで振って確かめた。その過程で使っていた公開データの一部が壊れていることが判明したので、それも記載する。

!

発見 — 公開データの破損

取引所差を調べるため同じ BTC を 2 つのソースで比較したところ、時間足リターンの相関が 0.00 だった（同一資産なら 0.99 以上になるはず）。切り分けの結果、ある公開データセットのバルク履歴が破損していた。価格水準は誤差 1bp 以内、年率ボラも誤差 2% 以内、欠損も重複も無い。壊れているのはバーの時刻と実際の値動きの対応だけで、統計量を見ても異常に見えない。

データ期間独立ソースとの相関判定
Bitstamp バルク履歴2012-01〜2025-010.03〜0.51破損
Bitstamp 日次更新2025-01〜0.9988正常
Huobi 6 銘柄2017-10〜2020-050.9986正常
Binance perp 7 銘柄2020-01〜2026-03基準正常

本戦略の検証（時代A・時代B・ホールドアウト）は Huobi と Binance だけを使っており、影響を受けない。影響したのは初期に行った「1〜15 分足に予測力があるか」の測定で、正常データで測り直したところ予測力は当初報告の 2〜3 倍あった（5 分足 IC 0.011 → 0.035）。それでも損益分岐には 2〜5 倍届かないため、短期は成立しないという結論自体は変わらない。再発防止に scripts/verify_data.py（独立 2 ソースの相関で破損を判定）とテスト 3 件を追加した。

コスト耐性 — 片道いくらまで成立するか

ホールドアウト全期間

想定は片道 1.5bp（指値優先）だが、損益分岐は 22bp 前後で想定の 13 倍まで耐える。指値が一切約定せず成行のみ（2.5bp）でも Sharpe +0.94。約定が 8 時間遅れても +0.46、最悪の組み合わせ（10bp × 8 時間遅延）でも +0.12 で符号は反転しない。

銘柄数の制約 — 想定より軽い

GMO のレバレッジは 5 銘柄が上限。7 銘柄から選べる全組み合わせを総当たりした（ホールドアウト）。

銘柄数組合せSharpe 中央値範囲プラス率
3 銘柄35+0.94+0.26〜+1.52100%
4 銘柄35+0.94+0.40〜+1.38100%

どの銘柄数・どの組み合わせでもプラス。7→3 銘柄で失うのは中央値 0.05 だけ。GMO 相当（BTC/ETH/XRP）の +0.78 は 3 銘柄の中央値を下回るが、構造的な不利ではなく引きの悪い組み合わせだった。

統計的確度 — 3 つの独立した検定

当初は「t 値 1.07 で有意でない」と書いたが、これは最も検出力の低い検定だった。より適切な 3 つで測り直した。

検定対象結果
並べ替え検定（シグナルを無作為にずらす × 200 回）ホールドアウトのみヌル平均 −0.88 に対し実測 +1.07 → p = 0.010
四半期の符号検定（重複なしの独立区間）全期間 23 四半期18 勝 5 敗（78%） → p = 0.0053
ブロック・ブートストラップ（1 週間 × 2000 回）ホールドアウトのみ95%区間 [−0.71, +2.75]、P(Sharpe>0) = 88.9%
同上全期間 5.7 年95%区間 [+0.95, +2.55]、P(Sharpe>0) = 100%

最も重要なのは並べ替え検定。シグナルのタイミングを壊すと Sharpe は −0.88 に落ちる。つまりこの収益は「下げ相場でたまたまショートに寄っていた」という静的な傾きではなく、いつ建てるかの判断そのものから来ている。しかもホールドアウト内だけで完結した検定である。

残る唯一の制約

期間の短さ。ホールドアウト 1.18 年では、どんな検定を使っても「真の Sharpe が 1.0 なのか 0.3 なのか」までは判別できない（信頼区間 [−0.71, +2.75] がその幅）。これは時間でしか解決しない。逆に言えば、コスト・銘柄数・取引所・通貨・データ品質という他の懸念はすべて数字で潰した。
